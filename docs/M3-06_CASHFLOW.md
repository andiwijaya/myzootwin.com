## Financial proof and lifecycle contract

Compaction validates before folding and publishes a validated complete state. It preserves signed gross totals and counts for each financial kind, exact opening balance, accepted transaction count and last tick. Recent journal stays below128 entries during normal simulation. Original still-refundable build debit proofs retain net refunded amounts. Only pending Undo refunds pin their corresponding debit; closed refund/restore cycles are aggregated without retaining every obsolete object ID. Active admission proof and at most32 mission-pinned visitor IDs are retained; retired visitor serials are protected by a watermark and a bounded active-open list. The last-ticket display record alone cannot authorize an old visitor. Reward proof is bounded to the four V1 missions. World/proof limits reject malformed saves instead of silently dropping rights. Existing safe-integer/time/save-size guards remain finite numerical limits, not the old short-session history stop.

Every new financial UI action binds the serializable `economy.nextCommand` quote. Successful user financial operations consume it; failed/cancelled/replayed commands do not. Autonomous tickets/upkeep use independent stable visitor/period identity. Old quotes cannot become new purchases after a checkpoint or codec handoff, even if the same cell is reused. Resource generation uses this durable command sequence rather than an ephemeral editor counter. Future direct core callers must always pass `simulation.commandRevision()` captured at quote time; legacy omitted-command calls are supported only before the first archive. Removal quotes include the durable command; Undo also binds its command. No backend/cryptographic anti-cheat claim is made for user-editable local data.

Complete typed codec roundtrips preserve checkpoint and replay/refund/admission proof. The unpublished V1 foundation schema is extended; this is **not** M5 autosave or a published-save migration claim. Actual renderer retry/remount preserves whole page-session state. Actual full navigation/reload still starts a fresh entire preview:1500 coins, no expenses/refunds/receipts/visitors/world objects. It never revives paid visitor bodies without finances. M5 must implement durable saves, migrations and corruption recovery. M4-06's speed UI remains unchecked; current tests prove fixed-tick economics under different elapsed-time partitions and ten-tick scheduled batches, not a shipped10x control.

## State, event and transaction contract

`game/missions/engine.ts` owns typed mission quotes/views/statuses, initial reward definitions, actual-state evaluation and clone-only reward transaction logic. `game/core/simulation.ts` evaluates descriptive objectives before publishing each existing typed event, including `recovery-changed`, build/path/care/world/edit/tick/reset and successful claim. No extra event-bus subscriber, timer or RAF is added. Eligibility always rechecks actual topology, so a saved/UI descriptive `habitatConnected` flag cannot authorize reward. A mutable external snapshot is also re-evaluated without stale topology caching.

Claim validates the current mission/order/enabled predicate and quoted durable `economy.nextCommand`, then changes currency, positive reward ledger entry, completed IDs, reward reference, next mission and command together on a clone. The full strict codec must accept before the simulation publishes it. Stable `mission-q01` identity, completed/reward proof and current order prevent replay; failed/stale/paused/disposed/overflow claims publish nothing. Reward amount/provenance, prefix order, one-to-one enabled coin claim proof and archived reward counts are validated. Compaction retains reward proof in the bounded four-mission archive; ordinary spending/refund/ticket longevity remains unchanged.

The renderer saves the whole page-session snapshot on `mission-claimed`, renders authoritative views and forwards only quoted commands. Retry/remount retains money and progress together. UI never writes completion. Future mission consumers must keep **all real state event paths**, including assisted habitat/path construction, not only paid habitat-built events. Future **Q02 noncash unlocks need their typed outcome/codec contract added before enabling Q02**; this slice intentionally implements the verified positive-coin reward path, not zero-amount ledger entries or a pretend unlock. The existing ledger prohibits zero-value monetary transactions.

The unpublished V1 codec is strengthened without adding durable browser storage. M5 autosave, migrations, storage failure and reset confirmation are absent. Core reset restores its supplied constructor baseline; it is not a claim that every rehydrated simulation reset creates a fresh game. Actual full navigation/reload still creates the entirely fresh preview1500/no objects/no rewards; language preference alone persists. This is disclosed on-screen and tested.

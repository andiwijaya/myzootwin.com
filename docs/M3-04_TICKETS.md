## Payment contract

| Boundary | Result |
|---|---|
| Spawn, queue, corridor promotion | No receipt or income. |
| Cancel/close before actual gate crossing | Exit safely, no payment. |
| Crossing from gate into real connected path toward inhabited habitat | One10 ZC receipt, one ticket ledger entry, matching paid visitor decision and new position, committed together. |
| Empty habitat at entry | Permanent free entry for this ID; no retroactive charge when animals arrive. |
| No habitat, disconnected path, closed entrance, detached/forged/invalid body or inconsistent money | No admission transaction. |
| Paid guest later interrupted | Retain actual admission receipt once; no second charge/refund invented. |
| View completion, score, rendering, dropped/large frames, repeated commands/events | No extra payment. |
| Paid-state retry/remount/complete codec handoff | Preserve full matching proof; replay is idempotent. |
| Partial paid restore or malformed ledger | Reject without repair/recredit. |
| Full product reload before M5 | Fresh complete session1500/0 with no old visitor bodies; explicit UI note. |
| Financial history/balance limit | Pause intake/new admission with a clear localized reason, retaining all receipts. |

`game/economy/tickets.ts` owns data-only eligibility, reconciliation, limits and atomic idempotent payment. `game/visitors/graph.ts` narrowly extracts the existing pure topology helpers so tickets/navigation reuse the same path rules without a circular dependency. Navigation guards the actual movement step crossing a legal north/south gate neighbor. `visitor-admitted` is observational and emitted only after accepted state; handlers cannot independently award coins. The existing lifecycle-safe renderer records a complete in-memory memento immediately on admission. It adds no RAF, model or listener lifecycle.

`game-entry/ticket-feedback.ts` reads actual balance/admission/ledger totals and shows entry price, per-person pending/paid/free decision, last receipt and honest refresh boundary in ID/EN. No Collect-money button, frame-driven credit or fabricated satisfaction income. Build/care prices, maintenance/cashflow/recovery and durable save remain their later features. The unpublished V1 schema now requires explicit nullable entry provenance for legacy bodies/receipts; generated arrivals cannot bypass proof by pretending to be legacy data. Strict serialization is a contract test, not a shipped migration or localStorage autosave claim.

## Starting prices and transaction boundary

| Operation | Starting fictional ZC | Actual commit / recovery |
|---|---:|---|
| Habitat |300 | Legal footprint + occupancy + one build debit; duplicate live operation returns without spending. |
| Path tile |15 | One legal new cell + debit; duplicate occupied path does not charge. |
| Feeder / water / rest garden |80 /60 /80 | Actual safe resource placement + build debit together; no free object after affordability failure. |
| Food / water refill service |8 /4 | Fixed disclosed service fee, full target stock only on valid accepted request; full/stale/failed request costs0. |
| Maintenance |2 per habitat /60 simulation seconds | Due period settles once with a real debit; insufficient funds/space retain explicit due status. No habitat incurs no upkeep. |
| Structure removal |Actual paid construction amount returned | Trace the original build debit, refund only its remaining amount once; stock is discarded and refill fees stay spent. |
| World Undo |Repay exact prior refund | Restore occupancy/topology and reverse that refund atomically; insufficient repayment/duplicate/stale operation changes nothing. |
| Cancel or invalid action |0 | Authoritative state and ledger unchanged. |

`game/economy/prices.ts` is the shared data configuration. `spending.ts` prepares debits, upkeep and read-only financial/affordability/refund quotes. Existing `refunds.ts` retains provenance checks and now shares the absolute history bound. `createSimulation` validates cloned world/resource+money transactions before publishing and emitting events. Resource financial identities use ledger sequence with a separate removal namespace, so rehydration without ephemeral editor metadata does not reuse operation IDs or collide with world edits. Existing safe stock/animal behavior is unchanged; feeding/resting type unions only gain financial error reasons. Ticket admission remains its existing exact gate-crossing transaction, sharing the reserved normal-history boundary.

The UI reads authoritative money and quotes; it never owns a separate writable balance. Prices appear on confirm/refill/build actions and current-balance descriptions. Insufficient funds/history reasons are readable in ID/EN; placement ghosts use actual affordability. Resource removal dialogs disclose exact refundable construction, and Undo labels show repayment. Full/unsafe actions remain disabled. Money changes refresh placement validity, and recoverable stale financial reasons clear when funds become available. Renderer retry/remount preserves the same complete page-owner snapshot with no second RAF or subscriber.

The unpublished version1 save contract now includes `economy.maintenancePeriod`. Load validation requires the settled period to be within actual simulation time and covered by a matching real maintenance debit or subsequent construction/restoration proof when an active habitat exists. Complete paid-state serialization is tested; corrupt or partially restored money is not repaired by minting a replacement. This does not implement durable browser storage or a shipped migration. M5 must define those before release, including what to do with long-lived bounded histories.

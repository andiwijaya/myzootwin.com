## Player outcome and chosen objective rules

After claiming Q01, Q02 gives concise bilingual progress for each stable macaw: actual eating, actual drinking and current derived welfare. Its contextual action opens the relevant real bird/food/water/rest controls or returns to the aviary. The existing care controls remain functional and charge their real costs. Empty, unused or merely placed bowls/feeder do not qualify. Navigation and keyboard focus work when entering directly into a partially completed Q02 session; no inert care button or automatic completion.

The PRD specifies an initial threshold around60 and a small sustained duration, without a fixed duration number. This slice configures **both birds really fed and watered, and each welfare >=60 for50 consecutive100ms simulation ticks (5 seconds), after Q01 is claimed**. This is tunable game balance, not real animal husbandry. Real lifetime consumption before Q01 counts intentionally, including legitimate recovery supplies, but earns **no pre-prerequisite duration**. Pause/background stops ticks and freezes partial progress; there is no offline catch-up award. A below-threshold score, reserve/missing bird or unavailable care that reduces welfare resets an **unfinished** streak. Only the final fixed-tick publication adds duration; render calls, repeated reads, resource events and language changes cannot add time.

**An achieved5-second objective stays recorded before Claim.** Native candidate2 exposed an avoidable UX failure: the player had completed the real streak, but depleted supplies erased readiness while navigating to Claim. The final design retains the successful duration proof. Later welfare still changes honestly and can demand immediate care; UI explicitly distinguishes the recorded objective from current needs. Partial streaks still reset on failure. This qualification is not an invented success flag: actual two-bird use and consecutive fixed updates must first achieve50, and the codec preserves this bounded progress with its prerequisite/evidence constraints.

Claim Q02 unlocks original pastel **aviary flower trim** exactly once. It changes no coins and creates **no zero-value ledger entry**. Flowers actually render around the built aviary, disappear safely when it is absent, and return from the same-page saved proof after renderer recovery. Essential perches/food/water remain available before this cosmetic reward, avoiding a care prerequisite soft-lock. Q03 remains planned and Q04 locked; no visitor mission or badge is falsely marked implemented.

## State, proof and lifecycle

Mission rewards now have exclusive typed cash-proof or noncash-unlock shapes. Existing Q01 coin proof remains compatible. Q02 records its fixed unlock identity, claim tick and durable command alongside ordered mission completion/current mission in one clone transaction. The strict codec checks enabled mission/order, exact unlock type, bounded50-tick objective, real consumption counters, prerequisite timing, claim tick/nonce bounds and exclusive proof shape; unknown/duplicate/missing/future/cash-substituted proof is rejected without repair. Claimed state rejects replay regardless of journal folding. No UI event grants reward.

Financial compaction has one narrowly audited change: monetary reward IDs are selected only from cash-proof variants. Money totals, archived coin reward counts, ticket/refund/idempotence and old checkpoint logic are otherwise byte-for-byte equivalent after line-ending normalization. Noncash proof stays in the bounded four-mission state, outside the monetary journal. Long-session regression protection remains intact; the old960-entry freeze remains resolved.

The renderer uses its existing single RAF/core subscriber. The cosmetic scene owns one reusable geometry/material and disposes them independently. It synchronizes only on habitat changes or mission claims, avoiding another whole-state copy every render. Loading/retry/remount retains the entire authoritative snapshot and earned objective/proof. A **full browser reload still resets the entire preview to1500**, with no objects/rewards/unlock; language alone persists. This is page-session/codec durability, **not M5 autosave/cloud storage**.

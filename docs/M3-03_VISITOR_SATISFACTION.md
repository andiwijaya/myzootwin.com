## Scoring contract

| Experience | Actual result |
|---|---|
| Pending arrival/queue/unfinished observation | No fabricated score. |
| Completed view with animals present | Mean welfare per occupied observation tick, with empty periods0; round the30-tick mean to an integer. Score≥60 is satisfied, lower is concerned. |
| Partial animal presence | Score includes empty time; the UI separately reports occupied-time welfare and percentage of viewing time with animals. A hand-checked15 ticks at welfare100 plus15 empty ticks yields score50, observed welfare100 and50% presence. |
| Empty completed view |0, explicit empty habitat and welcome-animals action; no fake observed welfare. |
| No habitat / unreachable viewing spot | Distinct0-score access outcomes after a real bounded entrance greeting, with build/connect advice. |
| Interrupted view/queue | One terminal unscored result, specific close/access/removal/time-limit cause; keep genuine partial samples, exclude from the scored average. |
| Later care changes | Affect later observations; never rewrite a prior guest's result. Average is over scored visits, not a global current-welfare slider. |
| Queue pacing | No hidden waiting penalty. Preserve one corridor token/two FIFO bays and the documented wait; tune final pacing/attraction in M3-06. |

`game/visitors/satisfaction.ts` owns data-only sampling, immutable terminal outcomes and integer aggregate updates. Sampling accumulates integer welfare hundredths to avoid drifting floating totals. `game-entry/visitor-feedback.ts` presents localized non-color badges, explanations and bounded recent feedback. The renderer consumes the same existing models; no new3D face or animation-state claim. Active feedback is shown with that visitor; recent history excludes still-active IDs to avoid duplicate cards. Repeated updates do not spam unchanged status or retain stale locale/rows. Snapshot and view mutation cannot alter authoritative records.

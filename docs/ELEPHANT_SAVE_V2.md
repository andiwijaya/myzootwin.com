`save-v2.ts` strictly migrates the nine frozen V1 fixtures to schema 2 with the same currency, ledger, RNG, clock, missions, preferences, two macaws, original 120 tiles and legacy entities. This is intentionally a **migration-only schema**: it does not yet persist elephant residents, their ground states/resources, grant receipts or EH mission proof. Extending that strict union and the shared simulator is the next work. Never activate this backend against player saves until that seam and the remaining EH1-05 gates pass. Unknown elephant/grant content returns unsupported-schema so recovery cannot replace a newer save using an older supported backup.

Checkpoint/autosave accept an explicit codec; their default is the unchanged strict V1 codec. The opt-in backend uses the same database name and store, IndexedDB version 2, existing revision/generation CAS, and one simulator/ledger. Old binaries explicitly opening version 1 receive VersionError after upgrade. The existing connection closes on versionchange. The first original V1 checkpoint is preserved once at `elephant-v1-backup` in the same native write transaction as migration, including format-1-envelope and reset-first paths. Orphan backup data prevents a silent fresh start. Restart and Undo produce schema 2 and keep the original migration backup. No backend is added to the production entry point.

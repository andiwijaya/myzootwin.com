## Commit before credit

Grant preparation produces an immutable quoted candidate, validates Q04 proof, command revision, safe balance, stable operation ID and exact ledger/proof. It does not mutate the active world. The renderer quiesces its existing tick, and autosave drains prior writes before committing through the existing revision/generation CAS. The runtime adopts/publishes only the confirmed exact grant mutation, preserving latest preferences. Losing tabs retain their pre-claim balance and enter conflict; quota failure retains primary and session without optimistic credit.

Native UI exposed a self-race: an ordinary non-dirty in-flight autosave could be skipped by drain and collide with its own grant. The fix waits for in-flight work before dirty checks, reserves candidate scheduling and uses the committed candidate as the safe reader until the canonical runtime adopts it. Closing/flushing during a pending grant cannot restore the old uncredited reader over the committed grant. Seven grant tests include that regression, disposal/prefs, concurrent writers, quota retry, tampered candidate and retained compaction proof. Initial failure metadata remains ignored in `.qa/elephant-baseline/eh2-grant-ui-self-conflict.json`; no money was falsely shown or saved in that failed attempt.
